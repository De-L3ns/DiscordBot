# Feature Specification: Pokémon Collection Album

## Overview

The cardpacks app keeps a persistent Pokémon card collection for every Discord
user. Cards are collected automatically when a user successfully opens a pack.
The `/collection` command presents each configured set, its completion, its
cards, and an optional hit-only filter.

## Collection rules

- A card is stored once per user and originating pack set, with a quantity that
  increases on repeated pulls. Different finishes do not create extra entries.
- Every card generated by a pack is eligible for collection, including Basic
  Energy. Energy from an auxiliary API set belongs to the pack set that
  produced it.
- Pack consumption and collection insertion occur in one SQLite transaction.
  A card is not recorded if the user does not own a pack to consume.
- Collections begin when this feature is enabled; previously opened packs
  cannot be reconstructed.
- Existing collection databases that tracked finish variants are migrated to
  one entry per card on startup.

## Album behaviour

- `/collection` shows the caller's collection; `/collection user:@member`
  views another member's collection. Responses and controls are ephemeral to
  the command invoker.
- The initial selector lists every currently available pack set with collected
  and total card counts.
- A selected album lists all cards obtainable from that pack configuration in
  numeric card-number order. Owned cards have a checkmark and quantity;
  unowned cards are muted. Each entry shows card number, name, and rarity.
- The album header shows completion as a count and percentage.
- The detail selector contains only owned cards and shows that card's artwork
  and rarity. It returns to the current album page with the Back button.
- The `Hits` button switches between all available cards and only cards whose
  configured pull-rate outcome has `isHit: true`. This is the same source of
  truth used during pack generation.

## Performance and reliability

- Startup first uses a valid local card cache. The Pokémon TCG API is used only
  when a configured set has no valid cache.
- The validated source cards remain in memory after startup, so collection
  views do not repeatedly deserialize cache files or make API calls.
- Every collection view interaction is deferred before data work and then edits
  the original response, preventing Discord's three-second interaction timeout.
- The KletserBot card-back asset remains the pack-opening cover for hidden
  cards; the album intentionally uses a compact, attachment-free layout.

## Hit announcements

Set `CARDPACK_HIT_CHANNEL_ID` to a Discord text-channel ID to broadcast every
pulled hit. Each announcement names the user, shows the card rarity, and
embeds the card artwork. The announcement uses the same `isHit` configuration
that marks a pack-opening card as a hit. A missing or unavailable channel is
logged without preventing the pack from opening.

## Storage

Collection records live in the existing cardpacks SQLite database under
`CARDPACK_DATA_DIRECTORY`, alongside unopened-pack inventory. The database
stores the card identity and display snapshot needed to retain a user's
collection across bot and container restarts.
